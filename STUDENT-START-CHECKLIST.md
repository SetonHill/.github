# Student Start Checklist

Version: 0.3.0

- [ ] Use your own GitHub account and submit its exact username through the approved roster process.
- [ ] Enable two-factor authentication and accept the organization invitation.
- [ ] Confirm you can access only the course and team repositories assigned to you.
- [ ] Read the repository README, project definition, contribution guide, security policy, code of conduct, agent contract, and privacy rules.
- [ ] Clone the organization-owned repository; do not make a personal repository the authoritative course record.
- [ ] Confirm `main` is protected and the `verify` and `gitleaks` checks appear on pull requests.
- [ ] Copy `.env.example` to `.env` locally. Keep `.env`, credentials, and local configuration out of Git.
- [ ] Install and verify the repository's local secret safeguard. Remember that it supplements server checks.
- [ ] Practice the issue, branch, commit, push, pull-request, review, conflict-recovery, and squash-merge workflow using the instructor's safe exercise.
- [ ] Learn the required agent checkpoints and how to record output, disposition findings, support an advisory override, and document an outage.
- [ ] Know that a likely secret finding cannot be overridden: stop, do not reproduce it, and report privately through the official course channel.
- [ ] Expect access review when the course ends and possible archive or deletion six months later, subject to legal-hold, research, records, or IT exceptions.
- [ ] Use the announced export window only for a faculty-reviewed copy to your own private repository after teammate consent, licensing review, scans, and removal of private data. Public portfolio publication requires separate approval.
