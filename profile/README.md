# SetonHill on GitHub

Version: 0.2.0

The SetonHill GitHub organization supports supervised coursework, student software projects, faculty collaboration, and research activity. The organization serves students, instructors, and authorized collaborators who need a shared, durable record of planning, code, review, testing, and releases.

This organization is a course and research collaboration space. It is not an official Seton Hill University software service, production hosting platform, records system, or source of institutional policy unless the university explicitly designates it as such.

## How Repositories Are Used

Public foundation repositories may contain course documentation, safe examples, templates, and general learning resources. Graded student projects, team work, research in progress, private infrastructure material, and other restricted work belong in organization-owned private repositories created for the approved course or project.

Personal repositories and forks are not the authoritative record for assigned work. Course-specific instructions live in the assigned course repository and its approved companion materials. If an organization-wide policy and a course rule differ, follow the stricter rule and ask the instructor through the official course channel.

## Student Access

Students may use an existing GitHub account. Submit the exact username through the instructor's approved roster process, enable two-factor authentication, accept the organization invitation, and use only repositories assigned to you. Do not place usernames, rosters, private repository links, accommodations, or access exceptions in public issues.

Start with `STUDENT-START-CHECKLIST.md` and `STUDENT-POLICY.md`. Faculty begin with `FACULTY-PROVISIONING-CHECKLIST.md` and `FACULTY-POLICY.md`.

## Privacy and Security

Never commit passwords, tokens, private keys, recovery codes, `.env` files, student records, restricted research data, or private infrastructure details. Use synthetic, public, or specifically approved de-identified data. Report course-specific matters through the official course or syllabus channel. Report security matters through an approved private repository vulnerability-reporting mechanism when enabled or the university's official IT/security channel. Report conduct, accessibility, and privacy matters through official university channels. Do not post sensitive reports publicly.
